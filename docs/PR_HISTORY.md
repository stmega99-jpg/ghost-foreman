## #4 feat: 通知・緊急停止後は人間が許可するまで再開しない・実スロット停止・React画面

## 概要
ステップ4: 通知と遠隔回答、**緊急停止後は人間が許可するまで何も再開しない**仕組み、遠隔接続(Tailscale Serve)の手順。#3 はマージ済みで、このPRは main 向けです。

## 緊急停止(今回のレビュー対応)
停止すると永続的な「停止状態」(全体 / 案件 / スロット)が入り、**人間が明示的に解除するまで続く**。Gateway を再起動しても解除されない。

停止中に止まるもの(いずれも `backend/halt.py` の確認を通る):
- 実セッションへのメッセージ送信すべて: 自動回答、逆質問、会議の発注、判定係の呼び出し、人間の直接送信 (409)
- 新しい実スロット・AI会議の作成 (409)
- `foreman_*` ツールの自動承認
- 停止中に届いた確認は `held_emergency_stop` として記録するだけ。判定・回答・逆質問・通知はしない。AIには「再開しないで」と返す
- 人間の回答・会議の採用は、状態を変える**前に** 409 で拒否(中途半端に変わらない)

解除したとき:
- 停止中に届いた確認は `needs_human` になる。**自動では回答しない**。止まっていたスロットは `idle` で、自分では動き出さない
- 解除は確認ダイアログつき。全体・案件・スロット単位で解除できる。停止と解除は監査ログに記録

### 実機で見つけて直した穴
停止の直前に Gateway のキューに積んであったメッセージが、**停止後に走り出して作業が再開した**(実セッションで観測: `turn` が 1→2)。Gateway は止まったターンが終わるとキューの次を自動で始めるため。停止時に「キューを取り消す → 停止 → もう一度取り消す」へ変更し、同じ手順で再現しないことを確認 (取り消し1件、停止後 `turn=1` のまま、2通目は会話にも入らない)。

### 確認したこと
- ユニットテスト10件(`tests/test_halt.py`)。停止の確認を無効にすると 6 件が失敗することも確認
- 実機: 停止 → 再起動 → 停止が維持 → 解除 → 会話の行数が増えない・質問は未回答のまま `needs_human`・スロットは `idle`
- 実機: 停止中の直接送信 / 会議 / 回答は 409、AIの質問は `held_emergency_stop`、通知は0件
- 画面テスト21項目(赤いバナー、解除の確認ダイアログ、スロット単位の解除)

## 偽の「検証結果」を廃止 (別件で見つけたもの)
人間が「質問で返す」を押すと、担当AIの再確認として固定の作り話(「約2,000件」「約8倍速く」)が表示されていた。実接続のスロットでは、解説を LLM で生成し、再確認は実エージェントに送って実際の返答を表示するよう変更。模擬スロットだけ固定文を残し「【模擬】」と明示。

## #6 feat: iPhoneのホーム画面から Ghost Foreman を直接開く

## 概要
iPhone で Kiro Crew の管理画面ではなく、Ghost Foreman の画面を直接開き、ホーム画面のアイコンから起動できるようにします。**#5 の上に積んでいます**(#5 をマージしたら main へ向け直してください)。

## 仕組み
- 専用ページ `/api/apps/ghost-foreman/m/`。独自のマニフェスト・アイコン(幽霊)・名前「Ghost Foreman」を持つ
- **iOS はホーム画面アプリの保存領域(Cookie・Service Worker)を Safari と分ける**。そのため、ホーム画面アプリは追加元の URL(ログインリンク)で1回サインインし、以後は Gateway の **30日の更新用 Cookie** で自動延長する(マニフェストに `start_url` を書かないのはこのため)
- 20時間のアクセス用 Cookie が切れるとページ自体が 403 になるため、専用の Service Worker(範囲は `/api/apps/ghost-foreman/m/` のみ)がページと2つのモジュールだけを保存。API のデータは保存しない
- すべて切れたときは「サインインしてください」画面。貼り付けたリンクからはトークンの値だけを使い、貼り付けた URL へは移動しない
- React は同梱 (`ui/m/vendor/react.mjs`、19.3.1)。Gateway の `/vendor/` はダッシュボードの中でしか動かない部品だった。CDN は使わない
- 設定タブ: この iPhone の通知をオンにする / テスト通知を送る。通知のリンクも専用ページを開く

## 確認したこと
- **実 Gateway + 本物の Chrome(iPhone 表示)で16項目すべて合格** (`tests/ui/phone_e2e.mjs`): 直接表示、Safari での追加案内、アクセス用+更新用 Cookie、マニフェストとアイコン、Service Worker の範囲と保存内容、**アクセス用 Cookie 切れでも起動して自動延長**、全期限切れでサインイン画面(データは表示しない)、リンク貼り付けで再サインイン、トークンなしの URL は拒否、JS エラーなし
- ログインリンクは有効期限内なら複数回使える(実機で確認)。これがホーム画面アプリの初回サインインの前提
- ユニットテスト、画面テストともに合格

## 実機の iPhone でしか確認できないこと(未確認)
- ホーム画面への追加時に iOS がリンク(クエリ付き URL)をそのまま保存するか
- 通知の許可と実配信
- うまくいかない場合でも、サインイン画面からリンクを貼り付ければ使える

## セキュリティ上の判断
Kiro Crew は「tailnet のスマホ用 QR」では更新用 Cookie を出さない設計にしている。このPRは通常のログインリンクを使うため、**iPhone に30日間延長できるログインが残る**。毎日 QR を読み直す手間を避けるための選択で、範囲は tailnet 内に限られる。iPhone を紛失したときは Kiro Crew でログアウト(`/api/auth/logout`)して取り消すこと。

- 停止は、無料枠の上限やキーの問題としては扱いません。待機時間を設定せず、キーを「拒否」扱いにもしません。

## #11 fix: PCのダッシュボード画面が接続エラーになる（アプリ自身のAPIの権限を宣言）

## 問題

PC の Kiro Crew ダッシュボードで Ghost Foreman を開くと、次のエラーが出て、画面が何も表示されません。

> `[app-sdk] App "ghost-foreman" not permitted to access /api/apps/ghost-foreman/dashboard. Declared: [/api/slots, /api/chat/slots, …]`

## 原因

- ダッシュボードの画面は、ホームの SDK を通して通信します。この SDK は、アプリのマニフェストで宣言されたパス（完全一致、先頭一致、または末尾の `*`）にしか通信させません。
- Ghost Foreman の画面は、自分自身の API（`/api/apps/ghost-foreman/...`）を呼びますが、この宣言が**最初の雛形から入っていませんでした**。ほかのアプリは、すべて自分のパスを宣言しています。
- 今回の画面の作り直しが原因ではありません（作り直す前の画面も、同じ最初の通信で止まります）。今回、本物のダッシュボードを初めて実際に開いて、見つかりました。スマホ用ページは独自の通信方法なので、影響を受けていません。

## 変更

`permissions.api` に、アプリ自身のパスだけを追加します。

- `/api/apps/ghost-foreman`
